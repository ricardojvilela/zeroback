## BatchCutout Pro - Setup

### 1. Variáveis na Vercel

Adicionar:

- `SUPABASE_URL`
- `SUPABASE_ANON_KEY`
- `SUPABASE_SERVICE_ROLE_KEY`
- `SUPABASE_USERS_TABLE=batchcutout_users`

### 2. Auth no Supabase

Em `Authentication > URL Configuration`:

- `Site URL`: `https://batchcutout.com`
- `Redirect URLs`: adicionar pelo menos:
  - `https://batchcutout.com`
  - `https://batchcutout.com/`
  - `https://www.batchcutout.com`
  - `https://www.batchcutout.com/`

Sem isto, o login pode abrir e não devolver a sessão corretamente ao site.

Em `Authentication > Providers > Email`:

- ativar `Email`
- permitir `Email + password`

Se queres acesso imediato sem confirmação por email:

- em `Authentication > Providers > Email`
- desativar `Confirm email`

Sem o provider Email ativo, o login próprio com email e password não funciona.

### 3. Tabela no Supabase

```sql
create table if not exists public.batchcutout_users (
  id bigint generated by default as identity primary key,
  user_id uuid not null unique,
  email text not null,
  plan text not null default 'free',
  plan_status text not null default 'active',
  batch_limit integer not null default 2,
  monthly_image_limit integer not null default 0,
  monthly_images_used integer not null default 0,
  stripe_customer_id text,
  stripe_subscription_id text,
  current_period_start timestamptz,
  current_period_end timestamptz,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

create index if not exists batchcutout_users_plan_idx
  on public.batchcutout_users(plan, plan_status);
```

### 4. Ativar um utilizador Pro manualmente

Depois do utilizador criar conta e entrar pelo menos uma vez, executar:

```sql
update public.batchcutout_users
set
  plan = 'pro',
  plan_status = 'active',
  batch_limit = 100,
  monthly_image_limit = 2000,
  monthly_images_used = 0,
  current_period_start = date_trunc('month', now()),
  current_period_end = date_trunc('month', now()) + interval '1 month',
  updated_at = now()
where email = 'cliente@exemplo.com';
```

No painel `/admin`, esta ativação também pode ser feita pelos botões `Pro` e `Trial`.

### 5. Trial manual

Para trial:

```sql
update public.batchcutout_users
set
  plan = 'pro',
  plan_status = 'trialing',
  batch_limit = 100,
  monthly_image_limit = 2000,
  monthly_images_used = 0,
  current_period_start = now(),
  current_period_end = now() + interval '15 days',
  updated_at = now()
where email = 'cliente@exemplo.com';
```

### 6. Deploy

Depois de adicionar as variáveis na Vercel, fazer novo deploy para publicar:

- `api/auth-config`
- `api/account`
- `api/usage-reserve`
- `api/pro-users`

### 7. Comportamento atual
- Free: 2 imagens por lote
- Pro: 100 imagens por lote
- Pro: 2000 imagens por mês
- O site reserva o consumo antes de começar a processar
- O login é por email e password via Supabase
- O painel `/admin` permite listar contas e mudar entre `Free`, `Trial`, `Pro` e `Reset uso`
