## BatchCutout Pro - Setup

### 1. Variáveis na Vercel

Adicionar:

- `SUPABASE_URL`
- `SUPABASE_ANON_KEY`
- `SUPABASE_SERVICE_ROLE_KEY`
- `SUPABASE_USERS_TABLE=batchcutout_users`

### 2. Auth no Supabase

Em `Authentication > URL Configuration`:

- `Site URL`: `https://batchcutout.com`
- `Redirect URLs`: adicionar pelo menos:
  - `https://batchcutout.com`
  - `https://batchcutout.com/`
  - `https://www.batchcutout.com`
  - `https://www.batchcutout.com/`

Sem isto, o login pode abrir e não devolver a sessão corretamente ao site.

Em `Authentication > Providers > Email`:

- ativar `Email`
- permitir `Email + password`
- manter `Allow new users to sign up` ativo

Estado atual em produção:

- `Confirm email` está ativo.
- O envio de confirmação usa SMTP/custom email com Resend.
- O template profissional de confirmação está guardado e ativo.

Sem o provider Email ativo, o login próprio com email e password não funciona.

### 2.1 SMTP / Resend

Em `Authentication > SMTP Settings`, o SMTP/custom email está ativo com:

- Sender email: `noreply@batchcutout.com`
- Sender name: `BatchCutout`
- Host: `smtp.resend.com`
- Port: `465`
- Username: `resend`
- Password: chave API do Resend com `Sending access`
- Minimum interval per user: `60`

No Resend, o domínio `batchcutout.com` está verificado. Os registos DNS foram adicionados no Vercel para:

- MX: `send.batchcutout.com`
- SPF/TXT: `send.batchcutout.com`
- DKIM/TXT: `resend._domainkey.batchcutout.com`

Não guardar a chave API do Resend no repositório. Se a chave for rodada, atualizar apenas o campo `Password` no SMTP do Supabase.

### 3. Tabela no Supabase

```sql
create table if not exists public.batchcutout_users (
  id bigint generated by default as identity primary key,
  user_id uuid not null unique,
  email text not null,
  plan text not null default 'free',
  plan_status text not null default 'active',
  batch_limit integer not null default 2,
  monthly_image_limit integer not null default 0,
  monthly_images_used integer not null default 0,
  stripe_customer_id text,
  stripe_subscription_id text,
  current_period_start timestamptz,
  current_period_end timestamptz,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

create index if not exists batchcutout_users_plan_idx
  on public.batchcutout_users(plan, plan_status);
```

### 4. Ativar um utilizador Pro manualmente

Depois do utilizador criar conta e entrar pelo menos uma vez, executar:

```sql
update public.batchcutout_users
set
  plan = 'pro',
  plan_status = 'active',
  batch_limit = 100,
  monthly_image_limit = 2000,
  monthly_images_used = 0,
  current_period_start = date_trunc('month', now()),
  current_period_end = date_trunc('month', now()) + interval '1 month',
  updated_at = now()
where email = 'cliente@exemplo.com';
```

No painel `/admin`, esta ativação também pode ser feita pelo botão `Pro`.

### 5. Stripe

Criar no Stripe um produto `BatchCutout Pro` com estes Prices:

- Plano fundador mensal: `15 EUR` por mes
- Pro mensal: `19 EUR` por mes
- Pro anual: `190 EUR` por ano

Adicionar na Vercel:

- `STRIPE_SECRET_KEY`
- `STRIPE_WEBHOOK_SECRET`
- `STRIPE_PRO_EARLY_PRICE_ID`
- `STRIPE_PRO_MONTHLY_PRICE_ID`
- `STRIPE_PRO_ANNUAL_PRICE_ID`
- `BATCHCUTOUT_SITE_URL=https://batchcutout.com`

Configurar webhook no Stripe para:

- `https://batchcutout.com/api/stripe-webhook`

Ativar/configurar o Stripe Customer Portal para permitir gestão de cartão, faturas e cancelamento.

Eventos a enviar:

- `checkout.session.completed`
- `customer.subscription.created`
- `customer.subscription.updated`
- `customer.subscription.deleted`

O Checkout e o Customer Portal usam estes endpoints:

- `/api/create-checkout-session`
- `/api/create-billing-portal-session`
- `/api/stripe-webhook`

### 7. Comportamento atual
- Free: 2 imagens por lote
- Pro: 100 imagens por lote
- Pro: 2000 imagens por mês
- Plano fundador: 15 EUR/mês
- Pro Mensal: 19 EUR/mês
- Pro Anual: 190 EUR/ano
- O site reserva o consumo antes de começar a processar
- O login é por email e password via Supabase
- Novas contas precisam de confirmar o email antes do primeiro login
- O pagamento é feito por Stripe Checkout
- O webhook Stripe ativa/remove acesso Pro automaticamente
- O painel `/admin` permite listar contas e mudar entre `Free`, `Pro` e `Reset uso`
