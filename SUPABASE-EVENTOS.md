# BatchCutout - Eventos reais com Supabase

Estado: o codigo ja envia eventos para `/api/track`.

Enquanto o Supabase nao estiver configurado no Vercel, o endpoint responde com sucesso mas nao guarda dados.

## 1. Criar tabela no Supabase

No Supabase, abrir SQL Editor e executar:

```sql
create table if not exists public.batchcutout_events (
  id bigint generated by default as identity primary key,
  event_name text not null,
  event_category text,
  event_label text,
  page_path text,
  page_location text,
  language text,
  session_id text,
  visitor_id text,
  source text,
  campaign text,
  free_limit integer,
  value numeric default 0,
  detail jsonb not null default '{}'::jsonb,
  occurred_at timestamptz not null default now(),
  created_at timestamptz not null default now()
);

create index if not exists batchcutout_events_name_idx
  on public.batchcutout_events (event_name);

create index if not exists batchcutout_events_occurred_at_idx
  on public.batchcutout_events (occurred_at desc);

create index if not exists batchcutout_events_visitor_idx
  on public.batchcutout_events (visitor_id);
```

## 2. Variaveis no Vercel

No projeto Vercel, adicionar em Settings > Environment Variables:

- `SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY`
- `SUPABASE_EVENTS_TABLE` com valor `batchcutout_events`

Usar a `service_role key` apenas no Vercel. Nunca colocar esta chave no frontend.

Depois de guardar as variaveis, fazer redeploy.

## 3. Eventos guardados

Ferramenta:

- `tool_page_view`
- `tool_drag_upload_intent`
- `tool_upload_started`
- `tool_upload_added`
- `batch_limit_exceeded`
- `tool_processing_started`
- `tool_processing_completed`
- `tool_download_png`
- `tool_download_zip`
- `tool_pro_clicked`

Pagina Pro:

- `pro_page_view`
- `pro_cta_clicked`
- `pro_form_started`
- `pro_volume_selected`
- `pro_submit_attempt`
- `pro_waitlist_submitted`

## 4. Consultas uteis

Eventos por dia:

```sql
select
  date_trunc('day', occurred_at) as dia,
  event_name,
  count(*) as total
from public.batchcutout_events
group by 1, 2
order by 1 desc, 2;
```

Funil diario:

```sql
select
  date_trunc('day', occurred_at) as dia,
  count(*) filter (where event_name = 'tool_page_view') as visitas,
  count(*) filter (where event_name = 'tool_upload_started') as uploads_iniciados,
  count(*) filter (where event_name = 'batch_limit_exceeded') as tentativas_acima_3,
  count(*) filter (where event_name in ('tool_download_png', 'tool_download_zip')) as downloads,
  count(*) filter (where event_name = 'tool_pro_clicked') as cliques_pro,
  count(*) filter (where event_name = 'pro_submit_attempt') as tentativas_pro
from public.batchcutout_events
group by 1
order by 1 desc;
```
